Local candidate 0.1.0, not a published pin. Owner: 段成威. Desktop native produces and consumes this boundary; generated Rust and TypeScript are projections of `jsonschema/scheduled-tasks/execution-v1.schema.json`. There is no Host consumer, HTTP route, registered renderer command or executable scheduler in 3A. Identity references the existing storage authority. Earlier source families and fixed Runtime remain unchanged.

The new family is structurally additive; the complete 3A change is breaking due to Desktop schema 17 and reservation/outbox compatibility. Provider/reader support precedes emission. Supported/fallback checks remain those in supported-baselines.md; a family absent at those baselines also needs its own schema/actual-native conformance. Local candidate base/digests are in compatibility/scheduled-execution/source.lock.json; a dirty worktree is not a release source.

GrantConfirmation binds a user confirmation to the current plan revision, finite logical run count and UTC expiry. Native obtains owner/tenant/revision/capabilities afresh; input cannot supply identity, grant ID, permission mode or enable a plan. Replay returns the current original grant, never replenishes/rebinds it. Editing a plan invalidates its old grant. Reservations occupy quota in the same transaction; unknown does not refund. A grant is not an accepted run, tool approval, enabled plan, Provider HTTP budget or cost guarantee.

The separate read/manage/run capabilities are interpreted by the native exact-local policy using existing task/workspace capabilities, UI authorization for management, and grant/target/revision checks for run preflight. Merely adding capability strings to a renderer projection never authorizes execution. 3A preflight always ends in execution_not_ready after applicable checks. Public/production native authority is rejected.

WorkspaceReference is native-owned. user_project refers to the accessible existing chat project; managed_schedule refers to a plan's native allocation policy, not an already-created directory or user bookmark. Actual per-chat directory allocation/binding belongs to 3B. The request surface never takes raw paths.

RunView separates delivery state, native outcome and needs_attention; completed native turn does not attest business success. Operation/request/run/plan identities have independent roles. Manual retries reuse request and operation; rerun is a distinct explicit request; automatic logical slot is tied to plan schedule_epoch. 3A only has a transaction-internal manual reservation primitive, exercised with ordinary temporary fixtures; it is not exposed as a standalone production claim. The later combined transaction must add lifecycle/approval/continuity gates, occurrence, conversation and original outbox atomically before any real activation.

SQL schema is private to Desktop. The compatible reader withholds marked scheduled outbox rows even with the writer disabled. Schema 15 stays 15 on normal startup; older readers cannot open 17. 3A source is not evidence for any additional format introduced in 3B. Unknown high schemas/formats fail closed, without downgrading or resetting data.
