# Scheduled draft v1 · FEAT-155 3C-3B

Local candidate only, `0.1.0`; no release tag or production qualification. The authority is `jsonschema/scheduled-tasks/draft-execution-v1.schema.json` and `openapi/scheduled-plan-draft/scheduled-plan-draft.yaml`. The existing `plan-draft-v1` clarification/candidate is referenced, not copied into a shadow protocol. `generate-scheduled-draft.mjs` produces Go/Rust/TS types, a resolved validation schema and the fixed Runtime output schema; the candidate lock records every authority/generator digest and the Contracts base commit.

Owner: platform-team. Host (agent-runtime-team) provides five owner-only local bearer routes; Desktop (client-team) consumes native receipts. The Runtime protocol authority remains the fixed yijie-codex revision `6c1ad767f0997845b8258a1c452fd4eb7577579f`. User authorization covers this local implementation; it is not independent Consumer Owner approval or a publishable immutable pin.

Create accepts a public task ID and native workspace reference. Resume accepts only schema/policy versions. Turn accepts one bounded text value and an operation ID. No request accepts scope, filesystem paths, native thread/turn IDs, arbitrary config/outputSchema, attachments or permission mode. A successful receipt means accepted identity, never a valid candidate or a saved/enabled plan. Unknown versions, fields and purposes are closed errors. Unauthorized responses use the same closed family. Unknown/pending operation evidence must be recovered by existing read queries; it never licenses another POST.

The Host reserves immutable `scheduled_plan_draft` purpose before Runtime creation and includes purpose/schema/policy/workspace in operation identity. Ordinary resume/turn/permission/title paths cannot upgrade a draft. Native start, resume and turn share the fixed adapter and output schema. The exact input-only candidate is qualified by the native policy projection described in Host `docs/scheduled-draft-input-only.md` and FEAT-155 report29. Old fixed artifacts remain unqualified for drafts; Provider outputSchema support is still NOT RUN. Native root resolution accepts only an existing canonical empty child of a trusted scoped workspace root.

3C-3B3B adds `GET /v1/scheduled-plan-draft-session-mappings/{task_id}`. It reads the existing purpose/schema/policy/workspace and reserved/bound association without Runtime readiness, directory resolution or writes. Absent thread/responder is omitted (explicit null is invalid); bound requires a thread. The responder identifies this response, never the original sender. No query/body is accepted. Existing generic mapping and operation queries remain unchanged. The separate path avoids ambiguity with the existing resume route.

The private Desktop launch flag assembles only the isolated native candidate. Host validates its versioned native descriptor, canonical owner-only scope directories, parent and instance, then verifies the exact Runtime before opening Store6. This does not grant dispatch. Shared source is deployed before the new consumer; rollback stops producers and keeps compatible readers. No SQL23/Store7 is introduced in B3B.

Contracts' `runtime-input-only/source.lock.json` remains the Runtime-schema authority projection. Host consumes the native RPC; Desktop now mechanically receives this same lock solely for canonical-launcher artifact pins, not to call native RPC or invent permissions.

End-to-end impact is **breaking** because private candidate persistence advances Host 5→6 and Desktop 21→22. Ordinary startup stays Host5/Desktop15. New readers preserve 6/22 and refuse unknown purpose/format; old readers must not open candidate stores. To roll back, stop candidate producers normally and retain compatible readers; never rewrite 6 to 5 or 22 to 15. Install shared contracts and compatible readers before candidate writers, and qualify Runtime/Provider before enabling real sends. Current source locks are dirty-tree local evidence, not release pins.

Supported checks: `make scheduled-draft-generate`, `make scheduled-draft-check`, `make scheduled-draft-test`; `check-scheduled-draft-producer.mjs` validates actual captured Host/Desktop values. Four applicable baseline checks use `db4458fe94572c4df41a114005d54a049bb79b1f` (fallback), `f16a497e1377f45747f8ff9292b4b60cf2027f88`, `6f632f155eacdaf93df0e0b00b5dab9e369c5442`, and `811f38d6b104fa18477107e7ac91a85e19c445d1`.
