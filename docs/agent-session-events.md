# Agent Session Events v1

`AgentSessionEvent` is the stable contract for the Runtime Baseline 2 thread/turn slice.
Agent Host is the producer. Desktop and service/asynchronous consumers consume the
sanitized projection; they do not consume arbitrary Codex Runtime notifications.

- `task_id` is supplied by the business control plane;
- `agent_session_id` is generated by Agent Host;
- `codex_thread_id` and `turn_id` are generated by Codex Runtime;
- `event_id`, `stream_id`, `task_id`, `agent_session_id`, `codex_thread_id`, and
  `turn_id`, when present, are UUIDs; `item_id` is an opaque non-empty Runtime ID;
- `sequence` is strictly increasing only within one `stream_id`;
- delivery is at least once, so consumers deduplicate by `event_id`;
- a Host restart creates a new `stream_id`; mapping state survives, but old message deltas are not replayed;
- `turn.completed` is the authoritative turn terminal event;
- `error` is informational even when `will_retry=false`; it does not replace `turn.completed`;
- `warning` is always non-terminal.

## Discriminated event variants

`event_type` is the discriminator. IDs not listed for a variant are not permitted in
its JSON/SSE representation.

| `event_type` | Required contextual IDs | `terminal` | Payload |
| --- | --- | --- | --- |
| `thread.started` | none | `false` | non-empty `model`, `model_provider` |
| `turn.started` | `turn_id` | `false` | `status: in_progress` |
| `item.started` | `turn_id`, `item_id` | `false` | non-empty `item_type`; optional `text` |
| `item.agent_message.delta` | `turn_id`, `item_id` | `false` | required string `delta` |
| `item.completed` | `turn_id`, `item_id` | `false` | non-empty `item_type`; optional `text` |
| `turn.completed` | `turn_id` | `true` | `status: completed\|interrupted\|failed`; optional sanitized `code`, `message` |
| `error` | `turn_id` | `false` | required `message`, `will_retry`; optional sanitized `code` |
| `warning` | none | `false` | required `message`, `will_retry: false`; optional sanitized `code` |

The JSON Schema is a closed `oneOf` union: it binds every `event_type` to exactly
one payload shape, contextual-ID set, and terminal value. Empty delta and message
strings remain valid wire values, but producers must serialize the required field
rather than omit it.

## Cross-format authority

The JSON Schema is authoritative for JSON/SSE delivery. AsyncAPI references that
schema directly instead of copying its event enum. Protobuf carries the equivalent
semantic model for service and asynchronous consumers; its `AgentEventType` and
payload `oneof` must preserve the same pairing. `TurnLifecyclePayload.error_code`
and `error_message` map to JSON `code` and `message` on `turn.completed`.

Cross-contract tests fail when the JSON event variants, Protobuf enum/`oneof`, or
AsyncAPI payload reference drift. Protobuf cannot express every conditional rule,
so producers must additionally enforce the status, contextual-ID, and terminal
rules in the table above.

## Session failures

`AgentSession.failure_code` is an optional, stable, sanitized machine code. Producers
set it only when `AgentSession.state` is `AGENT_SESSION_STATE_FAILED` and omit it for
non-failed sessions. Adding the field at Protobuf tag 11 is wire-compatible with
consumers that do not yet know it.

Runtime-specific payloads are reduced to sanitized, stable fields rather than
forwarding arbitrary app-server JSON.
